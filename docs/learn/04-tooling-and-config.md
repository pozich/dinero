# 04. npm, package.json, tsconfig, Vite

Этот проект завязан на несколько инструментов, у каждого своя роль.
Это ближе всего к тому, что ты уже знаешь по dotfiles — конфиг-файлы,
которые читает конкретная программа.

## npm и `package.json`

`npm` — менеджер пакетов для JavaScript/Node.js (аналог `pacman`/`yay`,
но для JS-библиотек). `package.json` — его конфиг для ОДНОГО проекта:
какие библиотеки нужны и какие команды можно запускать.

```json
// package.json (реальный, целиком)
{
  "name": "dinero",
  "private": true,
  "version": "0.1.0",
  "type": "module",
  "scripts": {
    "dev": "vite",
    "build": "tsc && vite build",
    "preview": "vite preview",
    "tauri": "tauri",
    "test": "vitest run",
    "test:e2e": "wdio run e2e/wdio.conf.mjs"
  },
  "dependencies": {
    "@tauri-apps/api": "^2",
    "react": "^19.1.0",
    "react-dom": "^19.1.0"
    // ... и другие, см. SKELETON.md
  },
  "devDependencies": {
    "typescript": "~6.0.3",
    "vite": "^8.0.16",
    "vitest": "^3"
    // ... и другие
  }
}
```

- `"type": "module"` — файлы `.js` в проекте — это ES-модули
  (`import`/`export`), а не старый формат CommonJS (`require`).
- `"scripts"` — именованные команды. `npm run dev` на самом деле
  запускает `vite` (см. ниже). `npm run build` запускает `tsc &&
  vite build` — то есть **сначала** проверяет типы (`tsc`, ничего не
  собирает, просто проверяет и падает при ошибке типов), и **только
  если это прошло** — реально собирает продакшен-бандл (`vite build`).
- `"dependencies"` — библиотеки, нужные самому приложению в рантайме
  (React, Tauri API).
- `"devDependencies"` — нужны только во время разработки/сборки
  (TypeScript-компилятор, тестовый фреймворк, сам Vite) — в собранное
  приложение они не попадают.
- `^19.1.0` / `~6.0.3` — версия с допуском: `^` разрешает обновления,
  не ломающие совместимость по семантике semver (минорные/патчи),
  `~` — только патчи.

Команда, которую ты уже видел в этом проекте — `npm run tauri dev` —
на самом деле запускает `tauri` (CLI из `devDependencies`) с аргументом
`dev`. Это не обычный npm-скрипт из списка выше, а прямой вызов
установленного пакета `@tauri-apps/cli`. Про то, что конкретно он
запускает — глава 08.

## `tsconfig.json` — настройки компилятора TS

```json
// tsconfig.json (реальный, целиком)
{
  "compilerOptions": {
    "target": "ES2020",
    "lib": ["ES2020", "DOM"],
    "module": "ESNext",
    "moduleResolution": "bundler",
    "jsx": "react-jsx",
    "strict": true,
    "noUnusedLocals": true,
    "noUnusedParameters": true,
    "noFallthroughCasesInSwitch": true,
    "noEmit": true
  },
  "include": ["src", "tests"]
}
```

Ключевые поля:
- `"strict": true` — включает весь набор строгих проверок TS (среди
  прочего — нельзя неявно получить тип `any`, нельзя забыть
  проверить `null`). Без этого флага TS намного терпимее и пропускает
  больше потенциальных ошибок.
- `"noUnusedLocals"` / `"noUnusedParameters"` — ошибка компиляции, если
  объявил переменную/параметр и не использовал. Это буквально то, что
  ловит команда `npx tsc --noEmit`, которую запускают перед каждым
  коммитом в этом проекте.
- `"noEmit": true` — **TS в этом проекте не генерирует JS-файлы сам**.
  Он только проверяет типы (`tsc --noEmit` отдельно, как линтер); сам
  JS для браузера собирает Vite через свой собственный, более быстрый
  транспилятор (esbuild/Rolldown внутри Vite, который просто ОТБРАСЫВАЕТ
  типы, не проверяя их). Поэтому в `package.json` команда `build`
  явно запускает ОБА шага по очереди: `tsc && vite build` — проверка
  типов отдельно, сборка отдельно.
- `"include": ["src", "tests"]` — какие папки вообще проверяются; код
  в `src-tauri/` (это Rust, не TS) сюда не входит.

## Vite — дев-сервер и сборщик фронтенда

```ts
// vite.config.ts (реальный, целиком)
import { defineConfig } from "vite";
import react from "@vitejs/plugin-react";

export default defineConfig(() => ({
  plugins: [react()],
  clearScreen: false,
  server: {
    port: 1420,
    strictPort: true,
    watch: { ignored: ["**/src-tauri/**"] },
  },
}));
```

Vite делает две разные вещи в зависимости от команды:
- **`npm run dev`** (или когда её запускает Tauri) — поднимает
  локальный веб-сервер на `http://localhost:1420` с **Hot Module
  Replacement**: меняешь `.tsx`-файл — браузер/вебвью обновляет
  только изменённый кусок интерфейса, без полной перезагрузки
  страницы и без потери состояния (открытых диалогов и т.п.).
- **`npm run build`** (точнее, его вторая половина `vite build`) —
  собирает финальные статические файлы (`dist/`): минифицированный
  JS/CSS, разбитый на чанки (см. `dist/assets/*.js` после сборки —
  там отдельно лежит код для Аналитики, для Инвестиций и т.д., чтобы
  они подгружались только когда реально нужны, а не все сразу).

`port: 1420, strictPort: true` — фиксированный порт, потому что Tauri
(глава 08) при запуске в режиме разработки открывает окно, которое
смотрит именно на `localhost:1420`; если порт занят — `strictPort`
заставляет Vite упасть с ошибкой, а не тихо выбрать другой порт, на
который Tauri не пошёл бы.

`watch: { ignored: ["**/src-tauri/**"] }` — Vite не должен
перезапускаться из-за изменений в Rust-коде (у Rust — свой отдельный
watcher, через `cargo`, см. главу 08).

## Как эти команды складываются в `npm run tauri dev`

Когда ты запускаешь `npm run tauri dev`, происходит (в этом порядке):
1. Tauri CLI смотрит в `src-tauri/tauri.conf.json`, где написано, какую
   команду выполнить перед стартом (`beforeDevCommand`, в этом проекте
   — `npm run dev`, то есть Vite).
2. Поднимается Vite dev-сервер на порту 1420.
3. Tauri компилирует (если нужно) и запускает Rust-бинарник
   (`cargo run`), который открывает нативное окно.
4. Окно показывает вебвью, которое грузит страницу с того самого
   `localhost:1420` — то есть твой React-интерфейс.
5. Дальше любое изменение `.tsx`/`.ts`-файла подхватывается Vite "на
   лету" (шаг 2), а изменение Rust-файла — пересобирает и
   перезапускает бинарник (шаг 3).

Это объясняет, почему в логах `npm run tauri dev` видно одновременно и
строки от Vite, и `cargo check`/`Running target/debug/dinero` — это
два независимых процесса, запущенных одной командой.

## Итог главы

`package.json` — что есть и что можно запускать, `tsconfig.json` —
правила проверки типов (без сборки), Vite — реальный дев-сервер и
сборщик. В следующих двух главах — React (что именно Vite собирает) и
хуки, а дальше — SQL и Tauri, то, с чем React-код общается.
