# 05. React: компоненты, JSX, props, состояние

React — библиотека для построения интерфейса из **компонентов**:
обычных TS-функций, которые принимают данные и возвращают описание
того, что нарисовать. Vite (глава 04) собирает эти функции в код,
который вебвью (глава 08) реально отрисовывает.

## JSX — HTML внутри TS-кода

```tsx
function Greeting() {
  return <h1>Привет!</h1>;
}
```

`<h1>Привет!</h1>` — это не строка и не HTML в прямом смысле, это
**JSX**: синтаксис, который Vite превращает в обычный вызов функции
(`React.createElement("h1", null, "Привет!")`), просто читать это в
виде тегов удобнее. Файлы с JSX в этом проекте имеют расширение
`.tsx` (а не `.ts`) — это сигнал и компилятору, и редактору, что внутри
есть JSX.

Внутри JSX можно вставлять TS-выражения в `{ }`:

```tsx
function Greeting({ name }: { name: string }) {
  return <h1>Привет, {name}!</h1>;
}
```

## Компонент — функция, принимающая props

`{ name }: { name: string }` в сигнатуре выше — это и есть **props**
(сокращение от "properties"): данные, которые родительский компонент
передаёт дочернему, через синтаксис похожий на HTML-атрибуты:

```tsx
<Greeting name="Богдан" />
```

Реальный, полностью рабочий компонент из проекта — `SettingsScreen`
(весь файл, 34 строки, ничего не упущено):

```tsx
// src/features/settings/SettingsScreen.tsx
import { useState } from "react";
import { applyTheme, getStoredTheme, THEME_LABELS, THEME_ORDER, type ThemeId } from "../../app/theme";

export function SettingsScreen() {
  const [theme, setTheme] = useState<ThemeId>(getStoredTheme());

  function choose(next: ThemeId) {
    setTheme(next);
    applyTheme(next);
  }

  return (
    <div className="screen">
      <h2>Настройки</h2>
      <h3>Тема</h3>
      <div className="theme-picker">
        {THEME_ORDER.map((id) => (
          <button
            key={id}
            type="button"
            className={`theme-option ${id === theme ? "active" : ""}`}
            onClick={() => choose(id)}
          >
            <span className={`theme-swatch theme-swatch-${id}`} />
            {THEME_LABELS[id]}
          </button>
        ))}
      </div>
    </div>
  );
}
```

У этого компонента нет props вообще (сигнатура `SettingsScreen()` без
параметров) — он самодостаточен. Разберём остальное по частям.

## `useState` — состояние компонента

```tsx
const [theme, setTheme] = useState<ThemeId>(getStoredTheme());
```

`useState` — **хук** (функция, имя которой начинается на `use`,
подробнее про правила хуков — в главе 06). Он даёт компоненту
"память", которая переживает перерисовки:
- `getStoredTheme()` — начальное значение (вызывается только при
  ПЕРВОМ рендере компонента).
- `theme` — текущее значение (здесь типа `ThemeId`, см. главу 02 про
  union-типы — это буквально `"dim" | "amoled" | "slate"`).
- `setTheme` — функция, вызов которой (а) меняет значение и (б)
  говорит React "перерисуй этот компонент с новым значением".

Важно: `setTheme(next)` не меняет `theme` немедленно "на месте" —
она планирует новый рендер, в котором `theme` УЖЕ будет новым
значением. Внутри ТЕКУЩЕГО вызова функции `choose` переменная `theme`
осталась бы старой, если бы её читали после `setTheme` — но здесь она
и не используется после, так что это не всплывает.

## Рендер списка: `.map()` + `key`

```tsx
{THEME_ORDER.map((id) => (
  <button key={id} ...>
    {THEME_LABELS[id]}
  </button>
))}
```

`{ }` в JSX — это "вставь сюда результат TS-выражения". `.map()`
(глава 01) превращает массив `THEME_ORDER` (`["dim", "amoled", "slate"]`)
в массив JSX-элементов — ровно так, как рисуются списки в React:
обычным `.map()`, без специального "for"-синтаксиса.

`key={id}` — **обязателен** для элементов списка. React использует
`key`, чтобт между перерисовками понимать, какой элемент — тот же
самый (а не новый), а какой удалили/добавили — без этого React
начинает путать элементы местами при любом изменении списка
(например, сортировке), а бывает — и ломает фокус/состояние внутри
элементов списка. Значение `key` должно быть стабильным и уникальным
в рамках списка (тут это сам `id` темы — он не повторяется).

## Условная стилизация через шаблонную строку

```tsx
className={`theme-option ${id === theme ? "active" : ""}`}
```

Тройной оператор (глава 01: `условие ? а : б`) внутри шаблонной строки
— частый способ собрать CSS-класс: если `id === theme` (эта тема
сейчас выбрана), класс будет `"theme-option active"`, иначе просто
`"theme-option"`.

## Обработчики событий

```tsx
<button onClick={() => choose(id)}>
```

`onClick` — проп самого `<button>` (React предоставляет обработчики
для всех стандартных DOM-событий: `onClick`, `onChange`, `onSubmit`
и т.д.). Значение — функция, вызываемая при клике. Здесь это
**стрелочная функция, созданная на месте** (`() => choose(id)`), а не
просто `choose` — потому что нужно передать конкретный `id` именно
ЭТОЙ кнопки; если бы написали `onClick={choose}`, React вызвал бы
`choose(event)`, передав объект события вместо `id`.

## Условный рендер: показать что-то, только если...

Чуть более развёрнутый, но тоже реальный пример из
`src/features/files/FilesScreen.tsx`:

```tsx
{pending && (
  <ConfirmDialog
    title={pending.kind === "delete" ? "Удалить выписку?" : "Заменить выписку?"}
    onConfirm={confirmPending}
    onCancel={() => setPending(null)}
  />
)}
```

`pending && (...)` — если `pending` ложно (`null`/`undefined`/`false`),
весь `&&`-выражение вернёт это ложное значение, и React ничего не
отрисует (не бросит ошибку — `false`/`null`/`undefined` для React
значат "ничего здесь нет"). Если `pending` — объект (истинное
значение), `&&` вернёт правую часть — сам диалог. Это стандартный
React-идиом "показать компонент только при условии", используется в
проекте постоянно для модальных окон.

## Итог главы

Компонент — функция; JSX — то, что она возвращает; props — её
параметры; `useState` — её память между рендерами. В следующей главе —
остальные хуки (`useEffect` и другие) и конкретный реальный баг,
который случился в этом проекте из-за неаккуратного использования
одного из них.
